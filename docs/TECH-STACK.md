## เหตุผลของแต่ละตัว

### Vite
ตั้งค่าน้อย dev server เร็ว มี template `react-ts` พร้อมใช้
และใช้ config ร่วมกับ Vitest ได้ ไม่ต้องตั้งค่า test runner แยก

### Vitest + Testing Library
REQUIREMENTS §5 กำหนดว่าต้องมีทั้ง unit test ของสูตรและ component test ของ UI
Vitest ครอบคลุมทั้งสองอย่างด้วย config เดียว — การเพิ่ม Jest แยกจะเป็น dependency
ที่ซ้ำซ้อนโดยไม่ได้อะไรเพิ่ม

### Recharts
เขียนกราฟเป็น React component ตรงไปตรงมา รองรับกราฟทั้ง 4 แบบใน REQUIREMENTS §3.2:
เส้น (เงินต้นคงเหลือ), แท่ง (เงินต้น vs ดอกเบี้ย), เส้นสองเส้นตัดกัน (break-even)
ทางเลือกอื่นอย่าง D3 ยืดหยุ่นกว่ามากแต่ต้องเขียนเองเยอะเกินความจำเป็นของโปรเจกต์นี้

### Tailwind CSS
เลย์เอาต์สองคอลัมน์ที่ต้องยุบเป็นคอลัมน์เดียวบนมือถือ (REQUIREMENTS §3.1)
ทำด้วย utility class ได้เร็วกว่าเขียน media query เอง

**หมายเหตุ:** Tailwind v4 เปลี่ยนมาใช้ CSS-first config ไม่ใช่ `tailwind.config.js` แบบ v3
ตัวอย่างส่วนใหญ่บนอินเทอร์เน็ตยังเป็น v3 — อย่าลอกมาใช้ตรงๆ

### State: `useState` + Context เท่านั้น
state ของแอปคือชุดพารามิเตอร์สินเชื่อสองชุด (ปัจจุบัน / ทางเลือก) ไม่มี async
ไม่มี cache invalidation ไม่มี state ที่แชร์ข้ามหน้า — Redux/Zustand จะเป็น
ความซับซ้อนที่ไม่ได้แก้ปัญหาอะไร ถ้าภายหลัง state พันกันจนจัดการยากค่อยพิจารณาใหม่

### ฟอร์ม: `useState` เท่านั้น
ฟอร์มมีไม่กี่ช่องและ validation ตรงไปตรงมา (ตัวเลขบวก, อัตรา 0–100%)
ยังไม่ถึงจุดที่ react-hook-form คุ้มกับการเพิ่ม dependency

## การจัดการตัวเลข: ใช้ `number` ปกติ

**ตัดสินใจ:** ใช้ `number` ของ JavaScript ปัดเศษตอนแสดงผลด้วย `Intl.NumberFormat('th-TH')`

**ข้อจำกัดที่ยอมรับ:** JavaScript ใช้ IEEE 754 floating point ซึ่งแทนทศนิยมฐานสิบ
ได้ไม่แม่นยำ (`0.1 + 0.2 !== 0.3`) เมื่อวนคำนวณ 360 งวด ความคลาดเคลื่อนจะสะสม
ตัวเลขสรุปอาจต่างจากของธนาคารในระดับเศษสตางค์ถึงหลักสิบบาท

**เหตุผลที่ยอมรับได้:** REQUIREMENTS §1 ระบุว่าแอปนี้ตอบคำถามเชิงเปรียบเทียบ
("คุ้มไหม" "ประหยัดเท่าไหร่") ความต่าง 20 บาทจากยอด 600,000 ไม่เปลี่ยนคำตอบ

**เงื่อนไขที่ต้องเปลี่ยนใจ:** ถ้าภายหลังต้องการให้ตัวเลขตรงกับใบแจ้งหนี้ธนาคารเป๊ะๆ
ต้องย้ายไป `decimal.js` หรือเก็บเป็นสตางค์แบบ integer — การแยก `src/core` ออกมา
ทำให้เปลี่ยนได้โดยไม่ต้องแตะ UI

**สิ่งที่ test ต้องครอบคลุม:** ต้องมี test ที่ยืนยันว่าผลรวมของเงินต้นที่ตัดได้ทุกงวด
เท่ากับเงินต้นตั้งต้น (ภายใน tolerance ที่กำหนด) เพื่อจับกรณีที่ error สะสมเกินคาด

## โครงสร้างโฟลเดอร์

```
src/
  core/                 pure TypeScript — ห้าม import React
    interest.ts         ดอกเบี้ยลดต้นรายวัน
    amortization.ts     ตารางผ่อนรายงวด
    refinance.ts        เปรียบเทียบและจุดคุ้มทุน
    types.ts
    *.test.ts
  ui/
    components/
    App.tsx
docs/
```

**กฎของ `src/core`:** เป็น TypeScript ล้วน ห้าม import React หรือแตะ DOM/localStorage

เหตุผล: ตรรกะการเงินต้องเทสต์ได้โดยไม่ต้องเรนเดอร์ และ REQUIREMENTS §5 ระบุว่า
ต้องเอาผลไปเทียบกับตารางผ่อนจริงของธนาคาร — ถ้าตรรกะผูกกับ component จะทำได้ยาก
นอกจากนี้ยังเปิดทางให้เปลี่ยนวิธีจัดการตัวเลขภายหลังโดยไม่กระทบ UI

## ความเสี่ยงที่รู้อยู่

1. **TypeScript 7.0 เป็น major ใหม่** — เร็วกว่าเดิมมาก แต่เพิ่งออก
   tooling บางตัวอาจยังรองรับไม่เต็มที่ ถ้าเจอปัญหาตอนตั้ง scaffold ให้ถอยไป 5.x
   และบันทึกเหตุผลไว้ที่นี่

2. **Tailwind v4 เปลี่ยนวิธี config จาก v3** — เอกสารและตัวอย่างเก่ายังเป็น v3 เป็นส่วนใหญ่

3. **เวอร์ชันข้างบนยังไม่ได้ติดตั้งจริง** — ตัวเลขมาจาก `npm view` ยังไม่ได้ยืนยันว่า
   ทุกตัวทำงานร่วมกันได้ จะยืนยันเมื่อ scaffold สร้างเสร็จและรัน build/test ผ่าน
