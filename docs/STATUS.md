## ค้างอยู่ เรียงตามความสำคัญ

### 1. ⚠️ ยังไม่ได้เทียบตัวเลขกับตารางผ่อนจริงของธนาคาร

**สำคัญที่สุด และ AI ทำเองไม่ได้** — ต้องใช้เอกสารจริงจากธนาคาร

test ที่ผ่านทั้ง 96 ตัวพิสูจน์แค่ว่าโค้ดตรงกับสูตรที่เราเขียน ไม่ได้พิสูจน์ว่า
สูตรตรงกับที่ธนาคารคิดจริง ค่างวดที่ได้อยู่ในช่วงเดียวกับเครื่องคำนวณทั่วไป
แต่ยังไม่มีการยืนยันกับใบแจ้งหนี้หรือตารางผ่อนจริงแม้แต่ชุดเดียว

**วิธีทำ:** เอาตารางผ่อนจริงหนึ่งชุด กรอกตัวเลขเดียวกันลงแอป เทียบค่างวดและ
ยอดคงเหลือสัก 3-5 งวด ถ้าคลาดเคลื่อนเกินหลักสิบบาทแปลว่าสมมติฐานใน
[REQUIREMENTS §2.4](REQUIREMENTS.md) ข้อใดข้อหนึ่งผิด

### 2. Bundle ใหญ่ 650 KB (190 KB gzip)

Recharts กินพื้นที่เกือบทั้งหมด ยังไม่กระทบการใช้งานจริง
ถ้าจะแก้: code splitting หรือเปลี่ยนไปใช้ไลบรารีที่เล็กกว่า

## ตัดสินใจแล้ว อย่าเปิดประเด็นซ้ำ

- **กรอกยอดคงเหลือเอง** ไม่คำนวณย้อนหลังจากวงเงินเดิม + วันทำสัญญา
  เหตุผลอยู่ใน [REQUIREMENTS §7](REQUIREMENTS.md)
- **ใช้ `number` ปกติ** ไม่ใช้ decimal.js — เหตุผลและเงื่อนไขที่จะเปลี่ยนใจ
  อยู่ใน [TECH-STACK.md](TECH-STACK.md)
- **นับวันจริงของปฏิทิน** ไม่ใช้ 30 วันคงที่

## บทเรียนจากการทำครั้งนี้

เก็บไว้เพราะเป็นกับดักที่พลาดซ้ำได้ง่าย:

**การรันแอปจริงจับ bug ที่ test มองไม่เห็น** — ทั้งสามอย่างนี้ test ผ่านหมด:
แกนกราฟขึ้นเลขซ้ำและเส้นขาดกลางคัน, tooltip formatter ที่ tsc จับได้แต่ test ไม่จับ
เพราะไม่ได้ hover, และจุดคุ้มทุนที่แนะนำดีลขาดทุน

**ค่าเริ่มต้นที่ตั้งมั่วเผยกับดักจริง** — ตอนตั้งค่า default ของแอป ตัวเลขออกมาเป็น
ดีลที่ค่างวดถูกลงแต่ดอกเบี้ยรวมแพงขึ้น ซึ่งเป็นกับดักที่แอปนี้มีไว้เตือนพอดี
กลายเป็นเคสทดสอบที่ดีและทำให้เพิ่มคำเตือนใน UI

**ตัวเลข 30 วัน/เดือนทำให้คลาด 5 วันต่อปี** — 30 × 12 = 360 ไม่ใช่ 365
ทำให้ค่างวดต่างจากธนาคาร ~140 บาท/เดือน แก้โดยใช้วันจริงของปฏิทิน
รายละเอียดใน [TECH-STACK.md](TECH-STACK.md)

**สีกราฟต้องรันเครื่องมือตรวจ ไม่ใช่เลือกด้วยตา** — สีฟ้าอ่อนที่ดูดีตอนแรก
fail ทั้ง lightness band และ chroma floor

PowerShell 5.1 อ่านเป็น ANSI พอเขียนกลับเป็น UTF-8 ตัวอักษรไทยเสียหมด
(`เงินต้น` → `à¹€à¸‡à¸´à¸™`) เคยเกิดกับ `LoanForm.tsx` กู้ด้วย `git checkout`
ใช้ Edit tool แก้ทีละจุดแทน ช้ากว่าแต่ไม่ทำลายไฟล์
