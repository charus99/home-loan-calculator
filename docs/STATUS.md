## ค้างอยู่ เรียงตามความสำคัญ

### 1. ⚠️ ยังไม่ได้เทียบตัวเลขกับตารางผ่อนจริงของธนาคาร

**สำคัญที่สุด และ AI ทำเองไม่ได้** — ต้องใช้เอกสารจริงจากธนาคาร

test ที่ผ่านทั้ง 128 ตัวพิสูจน์แค่ว่าโค้ดตรงกับสูตรที่เราเขียน ไม่ได้พิสูจน์ว่า
สูตรตรงกับที่ธนาคารคิดจริง ยังไม่มีการยืนยันกับใบแจ้งหนี้หรือตารางผ่อนจริง
แม้แต่ชุดเดียว

**ทำง่ายขึ้นแล้ว** เพราะตอนนี้กรอกค่างวดจากใบแจ้งหนี้ได้ตรงๆ:

1. กรอกยอดคงเหลือ ค่างวด และอัตราจากเอกสารจริงลงคอลัมน์ซ้าย
2. เทียบ "หมดหนี้ใน ..." กับระยะเวลาที่เหลือตามสัญญาจริง
3. หรือเปิดตารางผ่อนรายงวด เทียบยอดคงเหลือสัก 3-5 งวดกับของธนาคาร

ถ้าคลาดเคลื่อนเกินหลักสิบบาท แปลว่าสมมติฐานใน
[REQUIREMENTS §2.4](REQUIREMENTS.md) ข้อใดข้อหนึ่งผิด — ที่น่าสงสัยที่สุดคือ
การใช้ 365 วันทุกปี และการนับวันจริงของแต่ละงวด

### 2. Bundle ใหญ่ 650 KB (190 KB gzip)

Recharts กินพื้นที่เกือบทั้งหมด ยังไม่กระทบการใช้งานจริง
ถ้าจะแก้: code splitting หรือเปลี่ยนไปใช้ไลบรารีที่เล็กกว่า

## ตัดสินใจแล้ว อย่าเปิดประเด็นซ้ำ

- **กรอกยอดคงเหลือเอง** ไม่คำนวณย้อนหลังจากวงเงินเดิม + วันทำสัญญา
  เหตุผลอยู่ใน [REQUIREMENTS §7](REQUIREMENTS.md)
- **ใช้ `number` ปกติ** ไม่ใช้ decimal.js — เหตุผลและเงื่อนไขที่จะเปลี่ยนใจ
  อยู่ใน [TECH-STACK.md](TECH-STACK.md)
- **นับวันจริงของปฏิทิน** ไม่ใช้ 30 วันคงที่
- **จุดคุ้มทุนคิดจากดอกเบี้ยที่ประหยัดสะสม** ไม่ใช่เงินที่จ่ายออก (2026-09-24)
  แบบเงินสดจะแบนราบเมื่อค่างวดเท่ากัน แล้วบอกว่าคืนทุนเดือน 194 ทั้งที่จริงคือเดือน 5
  และนับเดือนที่ติดบวก**ถาวร** ไม่ใช่ครั้งแรกที่แตะบวก กันโปรที่บวกช่วงแรกแล้วกลับไปติดลบ
- **คำนวณเมื่อกดปุ่ม** ไม่คำนวณสดทุกครั้งที่พิมพ์ (ผู้ใช้เลือกเอง 2026-09-24)
  ความเสี่ยงคือดูตัวเลขเก่าโดยไม่รู้ตัว จึงกันไว้: แก้แล้วยังไม่กด ผลลัพธ์จะจาง
  ตัวเลข "หมดหนี้ใน" ถูกซ่อน และมีข้อความเตือน

## บทเรียนจากการทำครั้งนี้

เก็บไว้เพราะเป็นกับดักที่พลาดซ้ำได้ง่าย:

**การรันแอปจริงจับ bug ที่ test มองไม่เห็น** — ทั้งสามอย่างนี้ test ผ่านหมด:
แกนกราฟขึ้นเลขซ้ำและเส้นขาดกลางคัน, tooltip formatter ที่ tsc จับได้แต่ test ไม่จับ
เพราะไม่ได้ hover, และจุดคุ้มทุนที่แนะนำดีลขาดทุน

**ค่าเริ่มต้นที่ตั้งมั่วเผยกับดักจริง** — ตอนตั้งค่า default ของแอป ตัวเลขออกมาเป็น
ดีลที่ค่างวดถูกลงแต่ดอกเบี้ยรวมแพงขึ้น ซึ่งเป็นกับดักที่แอปนี้มีไว้เตือนพอดี
กลายเป็นเคสทดสอบที่ดีและทำให้เพิ่มคำเตือนใน UI

**ตัวเลข 30 วัน/เดือนทำให้คลาด 5 วันต่อปี** — 30 × 12 = 360 ไม่ใช่ 365
ทำให้ค่างวดต่างจากธนาคาร ~140 บาท/เดือน แก้โดยใช้วันจริงของปฏิทิน
รายละเอียดใน [TECH-STACK.md](TECH-STACK.md)

**สีกราฟต้องรันเครื่องมือตรวจ ไม่ใช่เลือกด้วยตา** — สีฟ้าอ่อนที่ดูดีตอนแรก
fail ทั้ง lightness band และ chroma floor

**ห้ามแก้ไฟล์ที่มีภาษาไทยด้วย shell script** — `Get-Content -Raw` บน
PowerShell 5.1 อ่านเป็น ANSI พอเขียนกลับเป็น UTF-8 ตัวอักษรไทยเสียหมด
(`เงินต้น` → `à¹€à¸‡à¸´à¸™`) เคยเกิดกับ `LoanForm.tsx` กู้ด้วย `git checkout`
ใช้ Edit tool แก้ทีละจุดแทน ช้ากว่าแต่ไม่ทำลายไฟล์

**เครือข่ายนี้บล็อกการถาม DNS server ภายนอก** — คำสั่งที่ระบุ `-Server 8.8.8.8`
timeout ทั้งหมด รวมถึงโดเมนที่ปกติดีอย่าง google.com ใช้ DNS ของระบบแทน
(`Resolve-DnsName charus.xyz -Type NS`) และถ้าเจอ timeout ให้ทดสอบกับ
`google.com` ก่อนจะสรุปว่าโดเมนมีปัญหา

**`Invoke-WebRequest` อ่าน HTML ภาษาไทยเป็นขยะ** — ใช้ Latin-1 ทำให้ title
ดูเหมือนเสียทั้งที่ไฟล์ปกติ ถ้าต้องตรวจเนื้อหาเว็บให้ใช้
`$wc = New-Object System.Net.WebClient; $wc.Encoding = [System.Text.Encoding]::UTF8`

**console error `static.cloudflareinsights.com` ไม่ใช่ปัญหาของแอป** —
Cloudflare แทรก analytics script เข้ามาเอง และเครือข่ายนี้บล็อกโดเมนนั้น
ไม่กระทบการทำงาน

**`step` ของ input ทำให้ฟอร์มส่งไม่ได้แบบเงียบๆ** — ช่องค่าอากรแสตมป์เคยมี
`step={1000}` เบราว์เซอร์จึงถือว่า 1,200 ไม่ถูกต้อง แล้วบล็อก submit โดยไม่มี error
ให้เห็น ตอนนี้ฟอร์มใช้ `noValidate` เพราะแอปตรวจข้อมูลเองอยู่แล้ว และห้ามใส่
`step` ในช่องจำนวนเงินอีก (เคยเจอแบบเดียวกันกับช่องอัตราดอกเบี้ย)

**เปลี่ยนฟอนต์แล้วตารางดันหน้าเว็บล้นจอมือถือ** — ตัวเลขของ IBM Plex กว้างกว่า
ฟอนต์ระบบ ตารางผ่อนเลยกว้าง 483px บนจอ 390px และการ์ดที่เป็น grid item ขยายตาม
แก้ด้วย `min-w-0` ทุกครั้งที่เปลี่ยนฟอนต์หรือขนาดตัวอักษร ให้เช็ค scroll แนวนอนที่ 390px

**ตอนเทสต์ต้องดูว่าค่าเริ่มต้นค้างอยู่ไหม** — เคยสรุปผิดว่าแอปคำนวณพลาด
เพราะ script ทดสอบแก้อัตราดอกเบี้ยแค่ช่วงแรก ลืมว่าคอลัมน์ขวามีช่วงที่สอง
(4.75%) ค้างจากค่าเริ่มต้น พอลบออกแล้วตัวเลขตรงกับที่ core คำนวณเป๊ะ
ถ้าตัวเลขดูขัดสามัญสำนึก ให้คำนวณจาก core ตรงๆ เทียบก่อนสรุปว่าเป็น bug
