## 1. เป้าหมาย

เครื่องคำนวณสินเชื่อบ้านตามกติกาไทย ที่ช่วยตัดสินใจเรื่องเงินก้อนใหญ่ได้ด้วยตัวเลขจริง
ไม่ใช่แค่เครื่องคิดเลขค่างวด

**ผู้ใช้:** เจ้าของโปรเจกต์ใช้เองก่อน (คนเดียว) — ยังไม่ออกแบบเพื่อผู้ใช้ทั่วไป
ข้อนี้กำหนดว่าเวอร์ชันแรก **ไม่ต้องมี** onboarding, คำอธิบายศัพท์การเงิน, หรือระบบผู้ใช้

### คำถาม 4 ข้อที่แอปต้องตอบได้

| # | คำถาม | สิ่งที่ต้องแสดง |
|---|---|---|
| Q1 | ผ่อนเดือนละเท่าไหร่ ตลอดสัญญาเท่าไหร่ | ค่างวด, ดอกเบี้ยรวม, ยอดจ่ายจริงทั้งหมด |
| Q2 | ควรรีไฟแนนซ์ไหม คุ้มไหม | ส่วนต่างสุทธิหลังหักค่าใช้จ่าย + จุดคุ้มทุน |
| Q3 | ถ้าโปะเพิ่มเดือนละ X ประหยัดเท่าไหร่ | ดอกเบี้ยที่ประหยัดได้ + หมดหนี้เร็วขึ้นกี่เดือน |
| Q4 | ของธนาคารไหนคุ้มกว่า | เทียบข้อเสนอแบบเคียงข้างกัน |

**ข้อสังเกตเชิงออกแบบ:** Q2–Q4 ล้วนเป็นการ*เปรียบเทียบ* ไม่ใช่การคำนวณเดี่ยว
แกนกลางของแอปจึงเป็น "เทียบสอง scenario แล้วบอกส่วนต่าง" ไม่ใช่ฟอร์มคำนวณช่องเดียว

## 2. การคำนวณ

### 2.1 ดอกเบี้ยลดต้นรายวัน (effective rate)

ธนาคารไทยคิดดอกเบี้ยจากเงินต้นคงเหลือ ณ แต่ละวัน:

```
ดอกเบี้ยงวดนี้ = เงินต้นคงเหลือ × อัตราต่อปี × จำนวนวันในงวด ÷ 365
เงินต้นที่ตัดได้ = ค่างวด − ดอกเบี้ยงวดนี้
```

ผลที่ตามมาซึ่งต้องสะท้อนในแอป: **โปะแล้วเห็นผลทันทีในงวดถัดไป**
เพราะเงินต้นลดลงแล้วดอกเบี้ยวันถัดไปคิดจากฐานที่น้อยลง

### 2.2 ดอกเบี้ยขั้นบันได

กรอกเป็นช่วงปีได้เอง เช่น ปี 1–3 = 3.00%, ปี 4 เป็นต้นไป = 6.50%
รองรับจำนวนช่วงไม่จำกัด (โปรโมชันแต่ละธนาคารแบ่งช่วงไม่เหมือนกัน)

### 2.3 ค่าใช้จ่ายในการรีไฟแนนซ์

ต้องหักออกจากเงินที่ประหยัดได้ ก่อนสรุปว่าคุ้มหรือไม่:

- ค่าจดจำนอง (~1% ของวงเงิน)
- ค่าประเมินราคาหลักประกัน + ค่าอากรแสตมป์
- ค่าประกันอัคคีภัย / MRTA
- ค่าปรับไถ่ถอนก่อนกำหนด (prepayment penalty) — มักคิดเมื่อรีไฟแนนซ์ก่อนครบ 3 ปี

### 2.4 Assumptions ที่ยังไม่ได้ยืนยันกับแหล่งอ้างอิง

รายการนี้เป็น**ข้อสันนิษฐาน** ไม่ใช่ข้อเท็จจริงที่ตรวจแล้ว — ต้องยืนยันก่อน freeze สูตร:

1. **ใช้ 365 วันทุกปี** รวมปีอธิกสุรทิน — ธนาคารไทยส่วนใหญ่ทำแบบนี้ แต่ไม่ทุกเจ้า
2. **ค่างวดคงที่** ส่วนเกินจากดอกเบี้ยไปตัดเงินต้น — ถ้าดอกเบี้ยขึ้นจนค่างวดไม่พอจ่ายดอกเบี้ย
   (negative amortization) แอปต้องเตือน ไม่ใช่คำนวณเงียบๆ ต่อไป
3. **"ปี 1–3" นับจากวันทำสัญญา** ไม่ใช่ปีปฏิทิน
4. **งวดชำระตรงวันเดียวกันทุกเดือน** ยังไม่รองรับกรณีเลื่อนวันหยุด/เสาร์อาทิตย์

## 3. หน้าจอและฟีเจอร์

### 3.1 โครงหลัก: สองคอลัมน์เทียบกัน

```
┌──────────────────┬──────────────────┐
│ สินเชื่อปัจจุบัน  │ ทางเลือกใหม่      │
├──────────────────┼──────────────────┤
│ คงเหลือ 2.4M     │ วงเงิน 2.4M      │
│ อัตรา 6.5%       │ ปี 1-3: 3.0%     │
│ เหลือ 22 ปี      │ ปี 4+: 6.0%      │
│                  │                  │
│ งวด 18,500       │ งวด 15,200       │
│ ดอกรวม 2.1M      │ ดอกรวม 1.5M      │
└──────────────────┴──────────────────┘
        ↓ สรุปส่วนต่าง
  ประหยัด 612,000   คืนทุน 14 เดือน
```

โครงนี้ตอบ Q2–Q4 ได้ด้วยหน้าเดียว เปลี่ยนแค่ว่าคอลัมน์ขวาคืออะไร
(ข้อเสนอรีไฟแนนซ์ / ธนาคารอีกเจ้า / แผนโปะ)

### 3.2 กราฟและตาราง

1. **กราฟเงินต้นคงเหลือลดลงตามเวลา** — เทียบสองเส้นในกราฟเดียว เห็นว่าหนี้หมดเมื่อไหร่
2. **กราฟแท่งเงินต้น vs ดอกเบี้ยแต่ละงวด** — เห็นชัดว่าช่วงแรกจ่ายดอกเป็นส่วนใหญ่
3. **ตารางผ่อนรายงวดแบบเต็ม** — ทุกงวด: ค่างวด, ตัดดอก, ตัดต้น, คงเหลือ
4. **กราฟจุดคุ้มทุนรีไฟแนนซ์** — เส้นสองเส้นตัดกันเดือนไหน = คืนทุนกี่เดือน

### 3.3 การเก็บข้อมูล

`localStorage` เก็บในเบราว์เซอร์ — กลับมาไม่ต้องกรอกใหม่
ไม่มี backend ตัวเลขไม่ออกจากเครื่องผู้ใช้

### 3.4 ภาษา

- **UI:** ภาษาไทย
- **โค้ด คอมเมนต์ ชื่อตัวแปร commit message:** ภาษาอังกฤษ
- ตัวเลข/สกุลเงิน: รูปแบบไทย (`Intl.NumberFormat('th-TH')`)

## 4. ขอบเขตที่ไม่ทำในเวอร์ชันแรก

ตัดออกโดยตั้งใจ เพื่อให้เวอร์ชันแรกเสร็จจริง:

| ไม่ทำ | เหตุผล |
|---|---|
| ดึงอัตราดอกเบี้ยธนาคารอัตโนมัติ | ต้องมี backend + scraper และข้อมูลเพี้ยนง่าย — กรอกเองแทน |
| ระบบผู้ใช้ / ล็อกอิน | ใช้คนเดียว ไม่ต้องมี |
| คำนวณภาษี / ลดหย่อนดอกเบี้ยบ้าน | กฎซับซ้อนและขึ้นกับสถานการณ์ของแต่ละคน |
| แอปมือถือ / PWA / ออฟไลน์ | เว็บ responsive ใช้บนมือถือได้อยู่แล้ว |

รายการนี้ไม่ใช่ "ไม่ทำตลอดไป" — เป็น "ไม่ทำตอนนี้" เพิ่มทีหลังได้ถ้าจำเป็น

## 5. การตรวจสอบความถูกต้อง

CLAUDE.md กำหนดว่าห้ามอ้างว่าใช้ได้โดยไม่ verify — สำหรับแอปการเงินยิ่งสำคัญ
เพราะสูตรผิดแล้วคนเอาไปตัดสินใจเรื่องเงินหลักล้าน

- **Unit test** ตรรกะคำนวณทั้งหมด (ดอกเบี้ย, amortization, จุดคุ้มทุน, ค่ารีไฟแนนซ์)
- **ทดสอบ UI** ระดับ component สำหรับ flow หลัก
- เครื่องมือ: Vitest (ยังไม่ผูกมัด — ตัดสินใจตอนตั้ง scaffold)

**กรณีทดสอบที่ต้องมี** เพราะเป็นจุดที่พังได้ง่าย:

- ค่างวดไม่พอจ่ายดอกเบี้ย (negative amortization)
- งวดสุดท้ายที่เหลือเศษไม่ลงตัว
- โปะก้อนใหญ่จนปิดหนี้กลางคัน
- ดอกเบี้ยเปลี่ยนขั้นบันไดกลางสัญญา
- ปีอธิกสุรทิน (ถ้าเปลี่ยนใจใช้ 366 วัน)

**การตรวจสอบภายนอก:** ควรเทียบผลกับตารางผ่อนจริงของธนาคารอย่างน้อยหนึ่งชุด
ก่อนเชื่อผลลัพธ์ — การที่ test ผ่านพิสูจน์แค่ว่าโค้ดตรงกับสูตรที่เราเขียน
ไม่ได้พิสูจน์ว่าสูตรตรงกับที่ธนาคารคิดจริง

## 7. การกรอกยอดหนี้: กรอกยอดคงเหลือเอง

**ตัดสินใจแล้ว (2026-09-23):** ผู้ใช้กรอกเงินต้นคงเหลือปัจจุบันเอง
ไม่มีการคำนวณย้อนหลังจากวงเงินเดิม + วันทำสัญญา

**เหตุผล:** การคำนวณยอดคงเหลือย้อนหลังจะคลาดเคลื่อนถ้าเคยโปะเงินต้น
หรือถ้าอัตราดอกเบี้ยที่ผ่านมาไม่ตรงกับที่กรอก และผู้ใช้จะไม่รู้ตัวว่าตัวเลข
ที่เห็นเพี้ยนไปแล้ว ซึ่งขัดกับจุดประสงค์ของแอปที่เน้นความถูกต้อง (ดู §1)

**ผลที่ตามมา:** ผู้ใช้ต้องไปดูยอดคงเหลือจากแอปธนาคารก่อนใช้ ยอมรับความไม่สะดวกนี้
แลกกับตัวเลขที่เชื่อถือได้ `startDate` ใน `LoanTerms` ยังจำเป็นอยู่ แต่ใช้เพื่อ
นับจำนวนวันจริงในแต่ละงวด ไม่ใช่เพื่อคำนวณยอดคงเหลือ
